# 开发历程与成果

> 整理日期：2026-11-15。本文根据开发日志、历次交接文档、OTA 排障记录和代码实况净化整理，不包含账号、设备标识、WiFi、密钥、本机路径或私人对话。状态以当前源码与已记录的真机证据为准。

## 一、演进时间线

### A. MicroPython 原型（至 2026-11-11）

最初的硬件由 ESP32-S3-N16R8、SSD1306、ICS43434/MAX98357A 音频模块和按键组成。`单片机/` 中保留了教学实验、硬件诊断、设备和网关代码。

L7.5 首次打通：按键录音 2 秒 → 公网上传 → ASR → LLM → TTS → 设备播放。单轮约 15 秒，其中网络吞吐约 12.6 KB/s。排查发现主要瓶颈是 MicroPython lwIP 收发窗口，而非公网隧道；这促成 ESP-IDF 重写。

### B. 四层架构重写（2026-11-12）

形成当前四层工程：

1. ESP-IDF C++ 固件；
2. FastAPI 自建服务；
3. PySide6 桌面管理端；
4. Kotlin/Compose Android 用户端。

同时增加 `tools/virtual_device.py`，使语音协议可以在无硬件条件下联调。当日完成固件真实构建、服务端跨端契约修复和桌面端测试。云对话实测从原型约 15 秒降至约 7.54 秒，可选小綾路由约 6.45 秒。

### C. 公网连接与手机配网（2026-11-13）

设备使用自有服务器公网 HTTPS/WSS，不再要求与服务器位于同一局域网。Android 登录、添加机器人、BLE 扫描、写入 WiFi/服务器地址、认领设备和 WSS 上线的完整链路打通。

期间解决了代理剥离 WebSocket `Authorization` 的问题，改用 WebSocket 子协议传递凭据；修复 ERROR 恢复路径覆盖 OTA 周期导致的 66 秒重连，并明确语音会话 `start` 的采样率契约。

### D. 真机语音、账号隔离与 OLED（2026-11-13 晚）

固件 1.0.6 将下行音频帧池扩展到 2048 帧，真机语音流畅度得到确认。服务端加入两句 TTS 并行预取、按序播放及 done-only 回复回退。

账号路由按设备归属和用户角色决策：管理员进入专属语音链路，普通用户使用账号隔离的公共会话；长期记忆和管理员命令二次确认同步完善。OLED 实现八种本地动画、带外情绪事件及自动/手动表情分离。

### E. OTA 根因定位与真实升级（2026-11-13 至 11-14）

多个版本曾出现“下载和 SHA256 成功，但仍启动旧版本”。受控启动证明镜像本身可运行后，最终定位到 `esp_https_ota_perform()` 循环提前退出：最后一次正长度读取不代表状态已经进入 `SUCCESS`，必须继续读取到 0 字节，`esp_https_ota_finish()` 才会设置新启动分区。

修复后通过真实 API 完成 1.0.11 → 1.0.12 OTA，新槽启动、WSS/hello、自检取消回滚及镜像读回均通过。期间还区分了人工错误写入启动状态、暂态 WiFi 超时回滚等不同事件，避免把它们误归为同一缺陷。

### F. Android 0.2.0、保留身份改网与唤醒配置（2026-11-14）

Android 升级为蓝色铃铛视觉形象。已绑定设备可以复用 BLE 通道改网，服务端通过一次性授权和设备归属校验完成改网，不删除设备、不重新认领，保留原设备 ID、令牌和账号关系。

新增唤醒词配置链：App 编辑校验 → 服务端规范化与转发 → 固件 NVS 持久化 → `config_ack`。随后从“保存文本”升级为 MultiNet7 实际离线识别：服务端把完整中文短语转换为带上下文的无声调拼音，设备动态更新命令，成功保存后才确认配置。

### G. 模型分区、手机远程 OTA 与真机迁移（2026-11-14）

新分区布局包含双 `0x690000` 应用分区及 `0x2C0000` 模型分区。首次迁移通过完整烧录导入 `mn7_cn`，保留 NVS 配网和身份；启动确认真机运行 1.0.13、模型加载和 WSS 重连成功。

Android 增加兼容固件查询、更新确认、触发和事件轮询。设备只在 IDLE 且 WSS 已连接时检查更新；下载成功只代表等待重启，重新 hello 且版本匹配才代表新版本运行。

### H. 最终语音体验收尾（2026-11-14 晚至 11-15）

真机取证推动了几项关键修复：

- **情绪标记被朗读**：上游会把标记拆成不完整分片。服务端增加跨 delta 暂存和 TTS 最终边界二次净化。
- **自动表情缺失**：真实上游主要返回正文 delta/done，而非独立情绪事件。现从内联标记推导情绪，并在流末补发自动表情。
- **句尾听感缺失**：设备只接受完整 640 字节帧，服务端把短尾帧补静音到 640 字节。最终会话 209/209 帧完整播放，无丢帧和欠载。
- **唤醒后上游 HTTP 400**：空 ASR 文本仍进入 LLM。现直接提示“没有听清，请再说一次”，不调用 LLM，也不保存空消息。
- **语音状态覆盖 OLED 表情**：表情保留时只更新顶部状态栏；ERROR 保留 6 秒。
- **VAD 判停偏慢**：调整为能量阈值 200、静音 450ms；实测说完后约 460ms 结束。
- **WebSocket 文本/音频争用**：独立发送锁和脱敏断连分类保留，避免把不同网络故障混为一谈。

最终 1.0.13 镜像经哈希核验、真机启动和正式发布，默认唤醒词多轮识别成功，管理员语音链路多轮跑通，用户确认播放恢复正常。

## 三、保留的关键工程结论

1. **先分清证据层级**：源码完成、测试通过、构建成功、烧录成功和真机验收不能互相替代。
2. **OTA 必须读完整状态机**：收到全部字节不等于 OTA 状态成功，启动槽和 otadata 才是最终证据。
3. **流式文本需要边界状态机**：情绪标记可能跨任意 delta，净化必须支持不完整前缀，并在 TTS 输入前再检查。
4. **音频帧契约必须覆盖尾帧**：平均帧正常不代表短尾帧不会被设备丢弃。
5. **外部网络问题不与本地锁问题混淆**：发送锁、代理、隧道和远端关闭分别记录。
6. **发布安全优先**：真实凭据、数据库、Flash 备份、用户语音和原始运维日志不进入开源仓库；曾暴露的凭据需要轮换。
